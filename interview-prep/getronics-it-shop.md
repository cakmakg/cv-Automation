# RUNDE 2 — Technisches Fachgespräch (Teams, mit IT-Fachleuten)

**Wer:** Diesmal nicht HR, sondern **Techniker / Teamleiter IT Shop** (die Leute, mit denen du arbeiten würdest).
**Einsatzort:** **IT Shop bei HDI (Versicherung), Köln** — Walk-in-Support: Mitarbeiter kommen mit ihren Laptops/Problemen, du diagnostizierst, behebst oder gibst Ersatzgerät, dokumentierst.
**Was sie prüfen:** Ob du den Job *praktisch* kannst. Sie wollen **strukturiertes Vorgehen** sehen — NICHT auswendig gelerntes Lexikonwissen.

## 🎯 Die 6 goldenen Regeln fürs Fachgespräch
1. **Struktur vor Wissen.** Immer von einfach → komplex, von außen → innen, billigste/schnellste Prüfung zuerst.
2. **Laut denken.** Sie wollen deinen Denkweg hören, nicht nur die Lösung. „Erst würde ich X prüfen, weil…"
3. **Anwender einbeziehen.** Drei Standardfragen: *„Seit wann? Was wurde zuletzt geändert? Genaue Fehlermeldung?"*
4. **Eingrenzen / isolieren.** Reproduzieren, ein Faktor nach dem anderen ausschließen (anderes Kabel, anderer Port, anderer User, anderes Gerät).
5. **Dokumentieren + sauber eskalieren.** Im Ticket festhalten; wenn 2nd Level → mit klarer Doku weiterreichen.
6. **Ehrlich bei Lücken — aber mit Lösungsweg.** Nie raten/bluffen. „Das habe ich noch nicht im Detail gemacht, ich würde es so herausfinden: Doku/Kollege/Hersteller-Knowledge-Base."

## 🔐 HDI = Versicherung → Datenschutz ist Pflicht-Thema
Erwähne aktiv (das hebt dich ab und passt zum Kunden):
- **Vertraulichkeit / DSGVO:** Laptops enthalten sensible Kundendaten. Nie unbeaufsichtigt, **Bildschirm sperren (Win+L)**, keine Daten auf private Sticks.
- **BitLocker:** Geräte sind verschlüsselt → bei Reparatur/Neustart **Recovery-Key** nötig (kommt aus AD/Azure AD bzw. dem Tool des Kunden).
- **Datenträger-Entsorgung:** Bei Gerätetausch/Defekt → sicheres Löschen / fachgerechte Entsorgung der alten Platte.
- Verständnis dass in einer Versicherung **Prozesse, Berechtigungen, Nachvollziehbarkeit** streng sind.

## A) Hardware / Laptop-Troubleshooting (KERN der Stelle)

> Bei JEDEM Szenario: „Ich frage den Anwender nach Symptom/Zeitpunkt, dann gehe ich strukturiert von außen nach innen vor und dokumentiere."

**„Laptop startet nicht / kein Bild"**
→ Strom & Akku: Netzteil dran? Lade-LED? Akku evtl. tiefentladen → 10–15 Min laden. → Reagiert es (LEDs, Lüfter, Pieptöne)? → **Hard-Reset** (Netzteil + Akku ab, ~20 Sek Power-Knopf). → Kein Bild aber läuft → **externer Monitor** anschließen (Display vs. Grafik isolieren). → Boot-Reihenfolge/**BIOS** prüfen, „no boot device"? → Defekt vermutet → Ersatzgerät/2nd Level, Daten sichern.

**„Bluescreen (BSOD)"**
→ Fehlercode/Stopcode notieren. → Seit wann? Nach Update/Treiber/neuer Hardware? → **Abgesicherter Modus** → letzten Treiber/Update zurücknehmen. → **Event Viewer / Speicherabbild** prüfen. → RAM/Datenträger-Test (memtest, chkdsk).

**„Laptop ist sehr langsam"**
→ **Task-Manager**: CPU/RAM/Datenträger-Auslastung, welcher Prozess? → Autostart, zu viele Programme? → Datenträger voll? SSD vs. HDD? → Malware/Updates laufen im Hintergrund? → Temperatur/Lüfter (verstaubt → Drosselung).

**„Akku lädt nicht / hält nicht"**
→ Anderes Netzteil/Kabel testen, Ladebuchse prüfen, Akku-Zustand (Windows-Akkubericht / Hersteller-Tool), ggf. Akkutausch.

**„Überhitzung / laut"**
→ Lüftungsschlitze frei? Staub? Auf harter Fläche? Lüfter/Kühlkörper reinigen, ggf. Wärmeleitpaste (bei Befugnis), Temp-Monitoring.

**„Dockingstation: externe Monitore gehen nicht"** *(im Büro SEHR häufig!)*
→ Dock korrekt verbunden + mit Strom? → Dock-**Firmware/Treiber** aktuell? → Monitor-Kabel/Port tauschen (HDMI/DP/USB-C), anderes Kabel. → Windows „Projizieren" (Win+P) → „Erweitern". → Anzeigeeinstellungen / Auflösung. → Anderes Dock zum Isolieren.

**Bauteile, die du tauschen können solltest:** SSD/HDD, RAM-Riegel, Akku, Tastatur. → Sag: „Hardware-Tausch und Erstinbetriebnahme sind genau mein Ausbildungs- und Praxisbereich."

## B) Windows-Client (Win 10/11 im Unternehmen)
- **Anmeldeprobleme:** falsches Passwort vs. Konto gesperrt vs. Profil defekt vs. keine Domänenverbindung (Kabel/VPN). Erst eingrenzen.
- **Profil defekt / „temporäres Profil":** Symptom kennen, Lösungsweg über AD/Profil-Neuanlage andeuten.
- **Updates/Patches:** Windows Update, Neustart, bei Fehler Update-Cache leeren; im Unternehmen oft zentral gesteuert (WSUS/Intune).
- **Treiber:** **Geräte-Manager**, Treiber vom Hersteller, Roll-back bei Problemen.
- **BitLocker:** verschlüsselt, Recovery-Key aus zentralem Verzeichnis — Konzept sicher erklären.
- **Imaging / Rollout:** „Neues Gerät über ein **Image** aufsetzen, Standardsoftware, in die Domäne aufnehmen, Peripherie, Funktionstest, Einweisung, Doku."
- ⚠️ **Ehrlich bleiben:** Unternehmens-Tools wie **Intune / SCCM / Autopilot** → „Grundprinzip ist mir klar (zentrale Verteilung/Verwaltung), die konkrete Umgebung arbeite ich mich schnell ein." NICHT als Experte ausgeben.

## C) Active Directory / Identität
- Sicher: **Benutzer/Gruppen, Passwort-Reset, Konto entsperren, Gruppenmitgliedschaften, Computer in Domäne aufnehmen.**
- ⚠️ **Azure AD / Entra ID, M365:** „Grundlagen ja, vertiefte Admin-Themen arbeite ich mich ein." (Nicht überclaimen — dein Cloud-Hintergrund ist AWS, nicht Azure/M365.)

## D) Netzwerk-Basics (musst du locker erklären können)
- **Kein Netz:** Kabel/WLAN, Flugmodus, anderes Kabel/Port/Dose, anderer Rechner an gleicher Dose (Gerät vs. Leitung).
- **IP/DHCP/DNS** in einem Satz: IP = Adresse, DHCP = vergibt Adressen automatisch, DNS = übersetzt Name → IP.
- **VPN:** Remote-Mitarbeiter brauchen VPN für Firmenressourcen — kennen, dass Login/Zertifikat/Verbindung typische Fehlerquellen sind.
- **Diagnose-Befehle parat:** `ipconfig /all`, `ping`, `nslookup`, `ipconfig /flushdns`, `ipconfig /release` + `/renew`.

## E) Peripherie
- **Drucker druckt nicht:** physisch (Strom/Kabel/WLAN, Papier, Toner) → richtiger Drucker/Treiber → **Warteschlange** leeren → Testseite → Treiber neu / Spooler-Dienst neu starten.
- Monitore, Headsets, Maus/Tastatur, mobile Geräte — Standard-Setup + Funktionstest.

## F) Prozess / Ticketing / ITIL-Basics
- **1st vs. 2nd Level:** 1st = Erstannahme, Standardlösungen, Ticket erfassen; 2nd = tiefer/spezialisiert; sauber mit Doku weiterleiten.
- **Incident vs. Service Request:** Störung (etwas geht nicht) vs. Anfrage (neues Gerät/Software/Zugriff).
- **Priorisierung:** nach **Dringlichkeit × Auswirkung** (ein User vs. ganze Abteilung), **SLA** im Blick.
- **Doku:** alles im Ticketsystem — Symptom, Schritte, Lösung. „Nicht dokumentiert = nicht gemacht."

## G) Diagnose-Werkzeugkasten (nenn 3–4, das wirkt souverän)
`Task-Manager` · `Geräte-Manager` · `Ereignisanzeige (Event Viewer)` · `Datenträgerverwaltung` · `sfc /scannow` · `chkdsk` · `DISM` · `gpupdate /force` · abgesicherter Modus · Hersteller-Diagnose (Dell/Lenovo/HP).
